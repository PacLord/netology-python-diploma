# Сервис автоматизации закупок — Netology Procurement API

Дипломный проект курса Нетологии **«Python-разработчик: расширенный курс»** — REST API для автоматизации закупок в розничной сети. Сервис объединяет покупателей и поставщиков: позволяет управлять каталогом, корзиной, контактами доставки и заказами.

Проект реализован на Django и Django REST Framework. Веб-интерфейс покупателя не входит в состав репозитория; для изучения и проверки HTTP API предусмотрена документация Swagger UI, а для административных операций — Django Admin.


## Возможности

- Регистрация по email с подтверждением, вход по токену, просмотр и редактирование профиля, восстановление пароля.
- Каталог категорий, магазинов и товарных предложений; поиск и фильтрация товаров.
- Импорт и обновление каталога поставщика из YAML-файла по URL.
- Включение и отключение приёма заказов магазином.
- Управление контактами и адресами доставки (до пяти на пользователя).
- Корзина: добавление товаров, изменение количества и удаление позиций.
- Оформление заказа с проверкой складских остатков, фиксацией цены и адреса доставки.
- История и детали собственных заказов.
- Просмотр заказов поставщиком только в пределах своего магазина.
- Административное изменение статуса заказа; возврат товаров на склад при отмене.
- Email-уведомления покупателю и администратору об оформлении заказа, покупателю — об изменении статуса.
- Документация OpenAPI/Swagger и автоматические тесты.

## Запуск проекта локально

Ниже приведён пример для **Ubuntu / WSL2**. Для Windows без WSL или macOS команды установки PostgreSQL и активации виртуального окружения могут отличаться.

### 1. Подготовьте окружение

Потребуются:

- Python с поддержкой зависимостей из `requirements.txt` и модулем `venv`;
- PostgreSQL;
- Git.

Склонируйте рабочую ветку проекта:

```bash
git clone --branch develop https://github.com/PacLord/netology-python-diploma.git
cd netology-python-diploma
```

Создайте и активируйте виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 2. Создайте базу данных PostgreSQL

Если PostgreSQL ещё не установлен в Ubuntu / WSL2:

```bash
sudo apt update
sudo apt install -y postgresql
sudo service postgresql start
```

Откройте консоль PostgreSQL:

```bash
sudo -u postgres psql
```

Выполните SQL-команды:

```sql
CREATE USER netology_diploma_user WITH PASSWORD 'your-strong-db-password' CREATEDB;
CREATE DATABASE netology_diploma OWNER netology_diploma_user;
```

Выйдите из `psql`:

```sql
\q
```

Атрибут `CREATEDB` нужен для команды `python manage.py test`: Django создаёт временную тестовую базу. Это пример настроек **локальной** разработки; в продуктивной среде право создания баз следует убрать.

Если PostgreSQL уже установлен или база находится на другом сервере, используйте существующие реквизиты подключения.

### 3. Настройте переменные окружения

Создайте `.env` из примера:

```bash
cp .env.example .env
```

Откройте `.env` и заполните параметры. Пример конфигурации для локального запуска:

```dotenv
# Django
DJANGO_SECRET_KEY=replace-with-a-long-random-secret-key
DJANGO_DEBUG=True

# PostgreSQL
DB_NAME=netology_diploma
DB_USER=netology_diploma_user
DB_PASSWORD=your-strong-db-password
DB_HOST=127.0.0.1
DB_PORT=5432

# Публичный адрес приложения (используется в email-ссылках)
PUBLIC_BASE_URL=http://127.0.0.1:8000

# Письма отображаются в терминале, реальный SMTP не требуется
EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend
DEFAULT_FROM_EMAIL=noreply@example.com

# Получатель уведомлений/накладных о новых заказах
ORDER_NOTIFICATION_EMAIL=admin@example.com
```

Значение `DB_PASSWORD` должно совпадать с паролем, указанным при создании пользователя PostgreSQL. Для `DJANGO_SECRET_KEY` используйте собственное случайное значение, например сгенерированное командой:

```bash
python -c "from secrets import token_urlsafe; print(token_urlsafe(48))"
```

> **Важно:** файл `.env` содержит секретные данные и исключён из Git через `.gitignore`. Значения в примере предназначены только для локальной разработки. В продуктивной среде необходимо отключить `DEBUG`, корректно настроить `ALLOWED_HOSTS`, HTTPS, хранение секретов и реальную отправку почты.

### 4. Примените миграции и создайте администратора

```bash
python manage.py migrate
python manage.py createsuperuser
```

При создании суперпользователя используется **email**, а не `username`.

### 5. Запустите сервер

```bash
python manage.py runserver
```

После запуска доступны:

| Адрес | Назначение |
|---|---|
| http://127.0.0.1:8000/api/docs/ | Swagger UI — интерактивная документация API |
| http://127.0.0.1:8000/api/schema/ | Схема OpenAPI |
| http://127.0.0.1:8000/admin/ | Django Admin |
| http://127.0.0.1:8000/api/v1/ | Базовый префикс API |

**Обратите внимание:** `/api/docs/` и `/api/schema/` подключаются в проекте только при `DJANGO_DEBUG=True`. Сам `/api/v1/` является префиксом маршрутов, а не отдельной страницей.

## Первоначальные данные для демонстрации

После применения миграций каталог пуст.

1. Войдите в [Django Admin](http://127.0.0.1:8000/admin/) под суперпользователем.
2. Создайте пользователя-поставщика с типом `shop` (или измените тип существующего пользователя).
3. Создайте для него объект **Shop**, указав этого пользователя владельцем. Для демонстрационного файла `data/shop1.yaml` название магазина должно быть **«Связной»**, а приём заказов — включён (`state=True`).
4. Получите токен поставщика через `POST /api/v1/user/login`.
5. В Swagger UI выполните `POST /api/v1/partner/update` с токеном поставщика и ссылкой на доступный по HTTPS YAML-файл.

Пример тела запроса для каталога, включённого в репозиторий:

```json
{
  "url": "https://raw.githubusercontent.com/PacLord/netology-python-diploma/develop/data/shop1.yaml"
}
```

Импорт выполняется **по URL**: передача локального пути `data/shop1.yaml` в этот эндпоинт не поддерживается. Название магазина в YAML должно совпадать с названием магазина поставщика в базе. Повторный импорт обновляет предложения вместо создания дубликатов.

Для сценария покупки зарегистрируйте отдельного пользователя через API, подтвердите email, войдите и создайте контакт доставки.

## Авторизация и примеры запросов

Защищённые эндпоинты используют HTTP-заголовок:

```http
Authorization: Token <ваш_токен>
```

**1. Регистрация покупателя**

```bash
curl -X POST http://127.0.0.1:8000/api/v1/user/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "buyer@example.com",
    "password": "MySecurePassword123!",
    "first_name": "Иван",
    "last_name": "Иванов"
  }'
```

При локальном `console.EmailBackend` письмо с подтверждением появится **в терминале, где запущен Django**. Перейдите по ссылке из письма и подтвердите регистрацию. Без подтверждения новый пользователь неактивен.

**2. Вход**

```bash
curl -X POST http://127.0.0.1:8000/api/v1/user/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "buyer@example.com",
    "password": "MySecurePassword123!"
  }'
```

Пример успешного ответа:

```json
{
  "token": "your-auth-token"
}
```

**3. Просмотр каталога**

```bash
curl "http://127.0.0.1:8000/api/v1/products?search=iphone"
```

**4. Добавление товара в корзину**

Вместо `1` укажите существующий `ProductInfo.id`, который можно получить из каталога:

```bash
curl -X POST http://127.0.0.1:8000/api/v1/basket \
  -H "Authorization: Token YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "items": [
      {"product_info_id": 1, "quantity": 2}
    ]
  }'
```

**5. Оформление заказа**

Перед оформлением создайте адрес через `POST /api/v1/user/contact`, затем передайте идентификаторы собственной корзины и контакта:

```bash
curl -X POST http://127.0.0.1:8000/api/v1/order \
  -H "Authorization: Token YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "basket_id": 1,
    "contact_id": 1
  }'
```

Товары должны быть в наличии, а их магазины — принимать заказы. После оформления заказ получает статус `new`, остатки уменьшаются, цены и адрес доставки сохраняются как данные на момент покупки.

## Основные эндпоинты

Все пути ниже указаны относительно префикса `/api/v1/`. URL в проекте используются **без завершающего слеша**.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/user/register` | Регистрация |
| GET, POST | `/user/register/confirm` | Подтверждение email |
| POST | `/user/login` | Получение токена |
| GET, POST | `/user/details` | Профиль пользователя |
| POST | `/user/password_reset` | Запрос сброса пароля |
| GET, POST | `/user/password_reset/confirm` | Установка нового пароля |
| GET, POST, PATCH, DELETE | `/user/contact` | Контакты доставки |
| GET | `/categories` | Категории |
| GET | `/shops` | Активные магазины |
| GET | `/products` | Товарные предложения, поиск и фильтры |
| GET | `/products/{id}` | Детали товарного предложения |
| GET, POST | `/partner/state` | Состояние магазина |
| POST | `/partner/update` | Импорт YAML-каталога по URL |
| GET | `/partner/orders` | Заказы поставщика |
| GET, POST, PUT, DELETE | `/basket` | Корзина |
| GET, POST | `/order` | История и оформление заказов |
| GET | `/order/{order_id}` | Детали собственного заказа |
| PATCH | `/order/{order_id}/status` | Изменение статуса администратором |
| GET | `/orders` | Список заказов для администратора/поставщика |

`GET /products` поддерживает параметры `shop_id`, `category_id` и `search`. `GET /orders` поддерживает фильтр `state`.

Полное описание полей запросов и ответов, схем данных и кодов ошибок доступно в Swagger UI.

## Роли и права доступа

| Роль | Доступ |
|---|---|
| Гость | Регистрация, вход, восстановление пароля, публичный каталог |
| Покупатель (`buyer`) | Личный профиль, контакты, корзина, оформление и история собственных заказов |
| Поставщик (`shop`) | Личные операции, управление собственным магазином и каталогом, получение заказов со своими товарными позициями |
| Администратор (`is_staff=True`) | Django Admin, просмотр всех оформленных заказов и изменение их статусов |

Поставщик видит только позиции принадлежащего ему магазина, даже если заказ содержит товары нескольких магазинов. Пользователь не может оформить чужую корзину или использовать чужой контакт доставки.

## Статусы заказов

```text
basket → new → confirmed → assembled → sent → delivered
           |        |           |
           └────────┴───────────┴──→ canceled
```

`basket` — активная корзина, `new` — оформленный заказ. Администратор может отменить заказ из состояний `new`, `confirmed` или `assembled`. При отмене складские остатки восстанавливаются; повторная отмена запрещена. После `sent` отмена через API не предусмотрена.

## Email-уведомления

Для локального запуска используется `django.core.mail.backends.console.EmailBackend`. Сообщения выводятся в терминал без подключения SMTP-сервера.

- При регистрации отправляется письмо со ссылкой для подтверждения email.
- При оформлении заказа покупателю отправляется подтверждение, а на `ORDER_NOTIFICATION_EMAIL` — уведомление с накладной.
- При изменении статуса заказа покупателю отправляется уведомление.

Для реальной отправки почты настройте в `.env` SMTP-параметры (`EMAIL_BACKEND`, `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `EMAIL_USE_TLS` и др.).

## Автоматические тесты и проверка проекта

Запуск всех тестов:

```bash
python manage.py test --verbosity 2
```

Запуск тестов приложения заказов:

```bash
python manage.py test orders.tests --verbosity 2
```

Тесты заказов проверяют операции с корзиной, оформление, нехватку остатков, права доступа, историю заказов, email-уведомления, отмену и разграничение данных поставщиков.

Дополнительные проверки:

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
```
